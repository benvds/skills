# Point, main question and sub-questions

This file covers Phase 2 and Phase 3. The user formulates; you test and ask. Give your own formulations only after a real attempt, or when the user asks, and then as two or three options to choose from or combine.

## The point in one sentence

Ask: "What should your reader know, believe or do after reading? Say it in one sentence you could say out loud."

Test the attempt:

| Test | Passes | Fails |
| --- | --- | --- |
| It has a subject and a claim | "Teams decide better when everyone writes first and talks later" | "Something about meetings and decisions" |
| It fits one text of the planned length | one claim with a few supporting steps | three claims that each need their own article |
| It fits the reader from the brief | the reader cares about it and can follow it | it answers a question the reader doesn't have |
| Opinion piece: a reasonable person can disagree | "Remote-first teams should drop the daily stand-up" | "Good communication matters" |
| Informative article: it promises an answer | "Kopjes help readers remember, but only when they say something" | "An overview of headings" |

If a test fails, ask one question that makes the user see it. Examples:
- "Who would disagree with this, and why?"
- "If your reader remembers one sentence, which one should it be?"
- "Which of these three claims is the one you care about most?"

## The main question (reports)

A report answers one main question. Ask the user to write it. Test:

- **Answerable.** Can the question be answered with the time, data and sources at hand? "How do we become the best in the market?" is not; "Which three causes explain the drop in renewals in 2026?" is.
- **One question.** It asks one thing. "What causes X and what should we do?" is two questions; choose one as the main question and make the other a sub-question, or split the report.
- **Kind of answer.** Name what kind of answer it asks for: describing, explaining, comparing, evaluating or advising. The kind decides the sub-questions and the structure. An advisory question needs criteria; an evaluative question needs a standard.
- **Fits the client.** The answer is something the reader can use for a decision they face.

## Sub-questions

The sub-questions together answer the main question. Each one is needed, and you can answer each one on its own. This follows the common design rule for research questions in Dutch practice-oriented research: a main question with sub-questions that are each necessary and together sufficient.

Ask the user to write them. Then test:

1. **Together sufficient.** If all sub-questions are answered, is the main question answered? Ask: "Suppose you have all these answers. What is still missing for your main question?"
2. **Each needed.** Drop one sub-question in thought. Does the answer to the main question suffer? If not, it can go.
3. **No overlap.** Two sub-questions should not look for the same answer. Consultants call this MECE: mutually exclusive, collectively exhaustive. Use it as a test, not as a goal in itself.
4. **Answerable.** Each sub-question says where the answer comes from: data, sources, interviews, or the user's own experience.
5. **Order.** Usually: describe the situation, explain it, compare options, then judge or advise. The order of the sub-questions becomes the order of the sections.

Three to six sub-questions fit most reports and articles. More is a sign that the main question is too broad. With a budget, the number that fits can be smaller: a section needs at least two paragraphs (see `budget.md`).

## Questions the reader asks (articles)

For an article, the sub-questions are the questions your reader will ask, in the order they will ask them. Common ones:

- Informative article: What is it? Why does it matter to me? How does it work? What does it mean for me? What don't we know yet?
- Opinion piece: What do you claim? Why should I believe it? What is the best argument against it, and what is your answer? What changes if you are right?

Ask the user which questions their reader will have, and in which order. For an opinion piece, the strongest objection is always a sub-question.

## Opening frame: situation, complication, question

For a report or an article that must win a busy reader, the opening often follows situation, complication, question, answer (from Barbara Minto's pyramid principle): what the reader already agrees on, what changed or went wrong, the question that raises, and the answer, which is the point. Use it as a check on the point and the opening, not as a template for the whole text. If the user cannot fill in the complication, the text may not be needed yet.

## Mark where the answers come from

For each sub-question, ask the user where the answer comes from:

- **own experience:** the user's projects, observations and judgment. No research needed, but ask for a concrete example.
- **outside sources:** research, data, reports. This goes to background research (`research.md`).
- **both:** the user's experience, checked against what others found.

Save this per sub-question. It decides what goes to research and which paragraphs need the user's own examples.

## When the user is stuck

If the user cannot make a start after one question and one hint, switch: give two or three example formulations for their subject, each with a line on what it would mean for the text, and ask which comes closest. Then ask them to make it their own. Getting stuck is normal at this step; say so once, without fuss.
